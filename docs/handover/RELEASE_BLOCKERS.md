# قائمة معطلات الإطلاق الفورية والحرجة (Release Blockers)

يحتوي هذا المستند حصرياً على العقبات والمشكلات الفنية والمالية التي تمنع إطلاق منصة **Rentrix** للاستخدام الحقيقي في بيئة الإنتاج، وهي مرتبة تنازلياً حسب درجة الخطورة المحاسبية والتشغيلية ومرتبطة بمسارات الملفات الفردية وخطوات الإصلاح الموصى بها.

---

## 1. [RB-001] فشل اختبار حوكمة التواريخ بسبب UTC Slicing في تسوية أرباح الملاك

- **Severity:** P0 — Critical (تعطل الـ CI/CD واختبارات الحوكمة)
- **Area:** Financial Correctness / Timezone Safety
- **Route / File:** `rentrix-app/src/features/owners/services/owner-settlements-service.ts` (السطر 105)
- **Evidence:** فشل اختبار `src/lib/date-input-regression.test.ts` عند تشغيل أمر الفحص العام `pnpm test`.
- **Reproduction steps:**
  1. ادخل لجذر المشروع البرمجي.
  2. نفّذ الأمر: `pnpm test`.
  3. سيظهر فشل في الاختبار البرمجي ويشير إلى وجود العبارة غير الآمنة `toISOString().slice(0, 10)` داخل الملف المشار إليه.
- **Expected:** تمنع حوكمة النظام البرمجي بشكل قاطع استخدام `toISOString().slice(0, 10)` لحساب تواريخ الترحيل لأنها تتم بالتوقيت العالمي UTC مما قد يؤدي لإزاحة العمليات المالية يوماً واحداً إلى الخلف حسب منطقة تصفح المستخدم الجغرافية (سلطنة عمان GMT+4)، والبديل هو استخدام دالة منسقة محلية آمنة.
- **Actual:** تم جلب التاريخ الافتراضي لترحيل المصاريف الناتجة عن تصفية دفعات الملاك بصيغة UTC Slicing في حال غياب قيمة الـ `payout_date`.
- **User impact:** انحراف تواريخ المعاملات المحاسبية يوماً واحداً، وفشل تجميع واختبارات الـ CI/CD يمنع تسيير تذاكر النشر المؤتمت.
- **Data / financial / security impact:** عدم تطابق المعاملات مع تواريخ كشوفات الحسابات البنكية الفعلية يهدد جودة وموثوقية الإقفال المالي السنوي.
- **Recommended fix:** استبدال السطر المشار إليه بالصيغة المحلية الآمنة والخالية من تداخلات المناطق الزمنية:
  `expense_date: payload.payout_date || new Date().toLocaleDateString('en-CA')`
- **Release blocker:** Yes
- **Confidence:** High

## 2. [RB-002] تسويات أرباح الملاك والعمولات التشغيلية معزولة وتعمل ببيانات وهمية (Mocked)

- **Severity:** P1 — High (إيهام مالي بوجود عمليات وهمية)
- **Area:** Owner Settlements / Core Accounting Ledger
- **Route / File:** `rentrix-app/src/features/owners/services/owner-settlements-service.ts`
- **Evidence:** الدوال `listOwnerSettlements` و `approveOwnerSettlement` و `processOwnerPayout` مكتوبة بمصادر بيانات ثابتة ومعزولة عن استدعاءات الجداول الخلفية في Supabase، وتعطي ناتج نجاح فوري `return true` دون تنفيذ عمليات حقيقية.
- **Reproduction steps:** 
  1. تصفح صفحة الملاك في مركز الإدارة المالي.
  2. افتح كشف تسوية أرباح مالك نشط وقم بالضغط على معالجة الدفع أو الاعتماد.
  3. تظهر علامة النجاح الخضراء ولكن لا يتم تعديل الأرصدة أو تقييد اليومية العامة فعلياً بقاعدة البيانات.
- **Expected:** ربط حركات الاستعراض والاعتماد والترحيل بقاعدة البيانات المباشرة والـ RPCs التي تمت صياغتها مسبقاً لحفظ حقوق الأطراف وخصم التكاليف.
- **Actual:** المنصة تعرض واجهة برمجية وهمية لا تترجم حركاتها لبيانات محاسبية حقيقية.
- **User impact:** تضليل المستخدم التشغيلي وإرباك حسابات الملاك والشركات لغياب ترحيل الدفعات.
- **Data / financial / security impact:** خطر فقدان الرقابة على حسابات تصفية الأرباح للعملاء والشركاء التشغيليين وضياع عمولات المكتب العقاري الفردية.
- **Recommended fix:** ربط شاشة تسويات الملاك بشكل مباشر بقاعدة البيانات وجلب البيانات الحية والتخلص تماماً من طبقة البيانات الوهمية (Mock Module).
- **Release blocker:** Yes
- **Confidence:** High

## 3. [RB-003] ميزة الأمانات وتأمينات المستأجرين (Tenant Deposits) وهمية وغير معروضة بالواجهة

- **Severity:** P1 — High (عمليات وهمية وكود معزول)
- **Area:** Financial / Tenant Ledger / Liability Tracking
- **Route / File:** `rentrix-app/src/features/financials/deposits/*`
- **Evidence:** المكون البرمجي الكامل `DepositsWorkspace` مهجور وغير مدمج باللوحة الرئيسية للحسابات ولا يمكن للمستخدم فتحه أو الاستفادة منه، وبالمثل يحتوي ملف خدمته `deposit-service.ts` على دوال مخصصة للاستخدام مع مصفوفة محلية وهمية (Mocked) وتعديل يرسل استعلاماً فارغاً ومقيداً بـ `.limit(0)` لتفادي الخطأ الإملائي في الحفظ المباشر.
- **Reproduction steps:** محاولة البحث عن خيار "تأمينات المستأجرين" أو "عقود الأمانة" في شريط القائمة الجانبي للمركز المالي أو الشاشات التشغيلية؛ الخيار غير متوفر ومخفي تماماً بالرغم من جاهزية كود الواجهة البصري.
- **Expected:** توفير مركز متكامل ومربوط بالخلفية وجدول حوكمة التأمينات `deposit_txs` لإيداع واستقطاع ورد أموال الأمانة للمستأجرين وخصم أضرار الصيانة منها عند الإخلاء وتسجيلها كالتزام قانوني على عاتق الشركة.
- **Actual:** كود الواجهة معزول وبعيد عن قنوات الإنتاج وجداول قاعدة البيانات النشطة.
- **User impact:** عجز المحاسب عن إدارة الودائع والتأمينات وحساب الرد والخصم من الوديعة بطرق معتمدة وقانونية.
- **Data / financial / security impact:** اختلال الميزانية العمومية للشركة لعدم تتبع التزامات الودائع والأمانات النقدية المستلمة من العملاء والخاصة بالعقارات.
- **Recommended fix:** إدراج علامة تبويب سادسة باسم "مبالغ الأمانة والتأمين" ضمن الواجهة المالية الموحدة وترقية كود الخدمة للاتصال المباشر بقاعدة البيانات وجدولها الفعلي `deposit_txs`.
- **Release blocker:** Yes (أو يتم تعطيل وعزل هذا المجلد كلياً وتأجيله بشكل معلن لمرحلة ما بعد الإطلاق لعدم التسبب في تضليل محاسبي).
- **Confidence:** High
